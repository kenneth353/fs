Introduction

Proposed local ride-hailing and motorcycle transportation system

Catbalogan Ride is a proposed local ride-hailing and motorcycle transportation system intended for Catbalogan City, Samar, Philippines. It is designed as a capstone project to demonstrate how a digital platform could help organize motorcycle-based passenger transport within the city by allowing passengers to request rides through a mobile application and enabling registered riders to receive, accept, and complete those ride requests.

The system is presented as a concept and academic proposal. It does not represent an existing commercial service, and it is not affiliated with any established ride-hailing company. The accompanying HTML document is a documentation and UI/UX prototype only — it does not include real GPS, real-time maps, real payments, a database, or a production backend.

Positioning Statement This project is a proposed capstone system composed of a Functional Specification and a UI/UX Design Specification. It is intended for academic presentation, panel review, and PDF submission. Any operational details such as fare amounts, coverage areas, and rider requirements are placeholders that require stakeholder confirmation.

1.1 Purpose of the Proposed System

The purpose of Catbalogan Ride is to propose a structured, digital way for passengers and motorcycle riders in Catbalogan City to connect for local trips. Instead of relying solely on informal arrangements, the proposed system aims to provide a single platform where:

  • Passengers can enter a pickup point and destination.
  • An estimated fare can be shown before confirming a ride.
  • A registered rider can receive and accept the request.
  • Both parties can see the status of the ride.
  • A record of the trip, payment, and rating can be stored.
  • Administrators can manage users, riders, and ride activity.

1.2 Local Context

Catbalogan City is the capital of Samar Province and is composed of urban and rural barangays. Motorcycle-based transport is a common and practical way to move around the city, especially for short-distance trips. The proposed system is therefore designed with this local context in mind: simple flows, landmark-friendly pickup and destination entry, and cash-based payment as a primary option.

Local Information Rule This document does not claim official Catbalogan fare rates, government regulations, transportation statistics, or existing operational service details. Where such information would be needed, it is marked [For Stakeholder Confirmation] or [To Be Determined].

1.3 Scope of This Document

This document combines two complementary specifications:

UXUI/UX Design Specification

Project Overview

What the system is and how it is intended to work

2.1 What Catbalogan Ride Is

Catbalogan Ride is a proposed ride-hailing and motorcycle transportation booking system for Catbalogan City. It consists of three connected application views:

Passenger App

Request and track rides
  • Register and log in
  • Enter pickup and destination
  • View fare estimate
  • Confirm booking
  • Track ride status
  • Pay and rate

Rider App

Receive and complete rides
  • Register and verify
  • Go online / offline
  • Receive ride requests
  • Accept or reject
  • Start and complete trips
  • View earnings and ratings

Admin Dashboard

Manage the platform
  • Manage users and riders
  • Verify rider accounts
  • Monitor rides
  • Review reports
  • Handle feedback
  • Configure settings

2.2 Intended Users

User Group Description Primary Need
Passengers Residents and visitors in Catbalogan City who need local motorcycle transport. A simple way to request a ride and know the estimated fare.
Riders / Drivers Registered motorcycle operators who are willing to accept passenger trips through the platform. A structured way to receive ride requests and record trips.
Administrators Personnel responsible for managing users, riders, rides, and system settings. Visibility and control over the platform’s operations.

2.3 General System Concept

The system follows a simple request-and-match concept:

Concept Flow
Passenger Requests a Ride
↓
System Computes Estimated Fare
↓
System Searches for Available Rider
↓
Rider Accepts Request
↓
Ride is Completed
↓
Payment, Rating, and History Recorded

2.4 How Passengers Request Rides

A passenger opens the app, logs in, enters a pickup point and destination, views an estimated fare, and confirms the booking. The system then searches for an available rider and shows the assigned rider’s information once the request is accepted.

2.5 How Riders Receive Requests

A verified rider logs in, sets their status to Online, and waits to receive ride requests. When a request arrives, the rider can accept or reject it. After accepting, the rider proceeds to the pickup point, starts the ride, and completes it at the destination.

2.6 How Administrators Manage the Platform

Administrators use a desktop-style dashboard to review rider applications, manage passenger and rider accounts, monitor ongoing and completed rides, review reports and feedback, and configure system settings such as fare parameters.

Prototype Limitation The HTML prototype simulates these flows with static data. It does not connect to real maps, GPS, payment gateways, SMS, push notifications, or a production database.

Scope and Limitations

What is included and what is explicitly excluded

4.1 In Scope

The following functions and deliverables are part of the proposed Catbalogan Ride system documentation and prototype:

  • Passenger registration and login (conceptual)
  • Rider registration and login (conceptual)
  • Ride booking flow with pickup and destination entry
  • Estimated fare display based on configurable parameters
  • Conceptual rider matching
  • Ride status lifecycle and status display
  • Simulated notifications for key events
  • Ride history for passengers and riders
  • Rating and feedback after completed rides
  • Profile management screens
  • Administrator management of users, riders, and rides
  • Rider account verification workflow (conceptual)
  • Fare configuration screen for administrators (conceptual)
  • UI/UX prototype mockups for passenger, rider, and admin
  • Functional and non-functional requirements documentation

4.2 Out of Scope

The following are explicitly excluded from the prototype. They may be discussed as future production features, but they are not implemented in the HTML file.

  • Real GPS or device location services
  • Real-time maps or map tile providers
  • Real payment gateway or e-wallet integration
  • Real database or server-side storage
  • Production-grade authentication or authorization
  • Real SMS or push notifications
  • Real-time driver tracking
  • Production backend or cloud infrastructure
  • Actual deployment to app stores or web hosting
  • Real fare collection, commission, or rider payout
Important Clarification All interactions shown in the HTML prototype are simulated. The prototype is a documentation and UI/UX artifact only. It is not a working ride-hailing service, and it must not be presented as one.

Target Users

Who the proposed system is designed for

The proposed system is intended for three groups of users who interact with Catbalogan Ride in different ways. Each group has distinct needs and expected interactions with the platform.

5.1 Passengers

Passengers are individuals in Catbalogan City who need a motorcycle ride from one point to another. They may be residents going to work, students going to school, or visitors moving around the city.

Primary Needs
A simple way to request a ride, know the estimated fare, and see the status of the ride until completion.
Expected Interaction
Register or log in, enter pickup and destination, confirm booking, track the ride, pay, and rate the rider.

5.2 Riders / Drivers

Riders are motorcycle operators who are willing to accept passenger trips through the platform. They must be registered and verified before accepting rides.

Primary Needs
A structured way to receive ride requests and a clear record of completed trips, earnings, and ratings.
Expected Interaction
Register, submit requirements, wait for verification, go online, accept requests, complete trips, and review history.

5.3 Administrators

Administrators are the personnel responsible for managing the platform. They review rider applications, manage user accounts, monitor rides, and configure system settings.

Primary Needs
Visibility over users, rides, payments, and feedback, plus the ability to configure fare-related and system-wide settings.
Expected Interaction
Log in to a dashboard, verify riders, manage accounts, monitor rides, review reports, and adjust settings.
Note The system is intended for use within Catbalogan City only. Any expansion beyond the city would require separate review and stakeholder approval.

User Roles

Responsibilities and permissions per role

Catbalogan Ride defines three user roles. Each role has its own responsibilities, main functions, permissions, and typical workflow.

6.1 Passenger

Aspect Description
Responsibilities Register, request rides, enter pickup and destination, view fare estimate, monitor ride status, complete payment, rate rider, view ride history.
Main Functions Registration, login, profile management, booking, tracking, payment, rating, and history.
Permissions Can create bookings, cancel bookings, view own ride history, and rate riders.
Typical Workflow Login → Enter pickup → Enter destination → View fare → Confirm → Track → Pay → Rate.

6.2 Rider / Driver

Aspect Description
Responsibilities Register, submit required information, go online/offline, receive ride requests, accept or reject requests, pick up passengers, start and complete rides, view ride history, view ratings.
Main Functions Registration, verification, online status, request handling, trip management, earnings, and history.
Permissions Can accept or reject ride requests, start and complete trips, and view own earnings and ratings.
Typical Workflow Login → Go online → Receive request → Accept → Navigate → Start → Complete → View earnings.

6.3 Administrator

Aspect Description
Responsibilities Manage users, manage riders, verify accounts, monitor rides, review reports, manage feedback, configure system settings.
Main Functions Dashboard, user management, rider verification, ride monitoring, reporting, feedback handling, and settings.
Permissions Can approve or reject rider accounts, suspend accounts, configure fare parameters, and view platform-wide reports.
Typical Workflow Login → Dashboard → Manage users → Verify riders → Monitor rides → Review reports → Configure settings.

13 Ride Completed Arrives at the destination. Marks the ride as completed and shows the final fare. Trip is finished.
14 Payment Pays using the selected method. Records the payment status (simulated). Payment is recorded.
15 Rating Rates the rider and optionally leaves a comment. Stores the rating. Feedback is submitted.
16 Ride History Views previous rides. Displays a list of past rides with details. Passenger can review history.
